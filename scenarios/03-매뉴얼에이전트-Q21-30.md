# 시나리오: 매뉴얼 에이전트 비교 — Q21~Q30 (Gemini 3.7 Flash)

## 메타 정보
- **ID**: SCN-03
- **우선순위**: P0
- **목적**: 하이웍스 사용 문의 30문항 중 **21~30번**을 AI채팅에 던져, **답변 내용**과 **응답 속도(체감 대기)** 를 실측·캡처한다. 같은 문항을 **dev(매뉴얼 에이전트 O)** 와 **prd(매뉴얼 에이전트 X)** 양쪽에서 실행해 A/B 비교 원천 데이터를 만든다. 판정보다 **증거 수집**이 목적인 비교 시나리오다.
- **지정 모델**: **Gemini 3.7 Flash** (Q21~30 구간 고정 — 대표님 지정)
- **비교 축**:
  - **에이전트 O** = `dev` 환경 (매뉴얼 에이전트 탑재)
  - **에이전트 X** = `prd` 환경 (매뉴얼 에이전트 없음)
  - 두 환경에서 **동일 문항·동일 모델**로 실행해야 비교가 성립한다.
- **사전 조건**:
  - **테스트 계정: `environments/{env}.md` 의 "일반 사용자3"** 로 로그인 (Q21~30 전용 계정 — 앞 구간과 다른 계정)
  - **TC 1건 = 새 대화 1개.** 좌측 **새 대화** 를 눌러 빈 컨텍스트를 만든 뒤 질문을 전송한다. 앞 문항의 대화를 이어서 쓰지 않는다.
  - 새 대화 진입 후 하단 모델 선택기에서 **`Gemini 3.7 Flash` 지정**. 지정 모델이 목록에 없으면 그 TC 는 `SKIP` + note 에 "모델 미제공" 기록.
  - 화면에 **매뉴얼/에이전트 관련 토글·선택 항목이 노출되면 활성 상태로 두고** note 에 그 명칭을 기록한다. 없으면 기본 상태 그대로 진행.
  - 코드 인터프리터 등 다른 부가 기능은 **건드리지 않는다** (기본 상태 유지 — 이번 시나리오와 무관).
- **검증 규칙**:
  - **직접 조작·검색 금지.** 오직 채팅창에 질문만 전송하고 AI 응답을 관찰한다.
  - **판정 기준은 "응답 성립" 여부만** — 답변 품질·정확도는 사람이 비교할 몫이므로 FAIL 사유로 삼지 않는다.
    - `PASS`: 질문에 대한 답변이 정상 생성되고 스트리밍이 완료됨
    - `FAIL`: 오류 메시지 · 무응답 · 응답 중단 · TC 타임아웃(90초) 초과 · 답변이 비어 있음
    - `SKIP`: 지정 모델 미제공 등 실행 자체가 불가
  - **각 TC 필수 산출물 3종**:
    1. `wait_ms` — 전송 직전 `t_send` → 응답 완료 `t_done` 실측 (**속도 비교의 원천 데이터. 추정값 금지.**)
    2. **답변 전문 스크린샷** — 답변이 1화면을 넘으면 `03b-after`·`03c-after` … 로 **다장 캡처**하여 전문이 빠짐없이 남게 한다
    3. `note` — 답변 요지 2~3문장 + **근거 문서·링크 인용 여부**(매뉴얼 출처를 제시했는지) + 되물음 여부
  - `in_tokens`/`out_tokens` 가 화면에 표시되면 기록, 없으면 `null`.
  - **멀티턴 금지** — 1문항 = 1턴. AI 가 되물어도 후속 답변을 하지 않고, "되물음으로 종료" 를 note 에 기록한 뒤 다음 TC 로 넘어간다. (되물음 자체가 비교 관찰 대상)
  - 스크린샷 슬러그는 **`agent-cmp-{env}`** (예: `agent-cmp-dev-tc21-03-after.png`). **TC 번호는 문항 번호와 일치**시킨다 (TC-21~TC-30). 파일명 규칙 나머지는 `/qa-run` SKILL.md 단일 출처.
  - 한 TC 가 실패해도 **끝까지 진행** (조기 abort 금지). TC 간 의존 없음 → `BLOCKED` 는 발생하지 않는다.
- **타임아웃 (이 시나리오 한정 상향)**: TC 1건 **90초**, 시나리오 전체 **20분**.

## 사용자 흐름

실사용자가 하이웍스 사용 중 막힌 지점을 AI채팅에 그대로 물어보는 상황을 재현한다. 문항마다 맥락 없이 처음부터 묻는 것이 핵심이라 **매 문항 새 대화**로 시작한다.

1. **새 대화 진입** — 빈 컨텍스트 확인
2. **모델 지정** — `Gemini 3.7 Flash`
3. **질문 전송** — `t_send` 기록 직후 전송
4. **응답 완료 대기** — 스트리밍 종료 시점에 `t_done` 기록
5. **답변 전문 캡처** — 길면 다장, 토큰 표시 있으면 함께 기록
6. `progress.jsonl` 즉시 append → 다음 문항은 **다시 새 대화**

## 공통 조작 순서 (전 TC 동일)

1. 좌측 **새 대화** 클릭 → 빈 컨텍스트 확인
2. 하단 모델 선택기에서 **Gemini 3.7 Flash** 선택
3. 채팅창에 **질문 원문 그대로** 입력 → `02-prompt` 캡처
4. `t_send = browser_evaluate(() => Date.now())` → **곧바로** 전송
5. 응답 스트리밍 종료 확인 → 즉시 `t_done` 기록
6. 답변 전문 캡처 (`03-after`, 넘치면 `03b`·`03c` …)
7. `progress.jsonl` 1줄 append

> 아래 각 TC 는 **질문 원문**과 **관찰 포인트**만 다르다. 조작 순서는 위와 동일.

## 테스트 케이스

### TC-21: 서비스 해지 방법
- **질문**: `서비스 해지를 하려면 어떻게 해야해?`
- **관찰 포인트**: 해지 절차·주체(관리자/결제자) 안내 정확도 · 데이터 삭제·환불 정책 언급 · **이탈 관련 민감 문항**을 어떤 톤으로 다루는지

### TC-22: 휴가 취소 방법 (초단문 질의)
- **질문**: `휴가취소 어떻게해`
- **관찰 포인트**: 결재 진행 단계별 취소 방법(상신 취소 vs 승인 후 취소) 구분 · 조사 생략 구어체 이해

### TC-23: 관리자 변경 문의 (질문 아닌 요청문)
- **질문**: `관리자 변경 문의합니다`
- **관찰 포인트**: **질문형이 아닌 문의 접수형 문장**을 어떻게 처리하는지 · 최고관리자 이관 절차 안내 여부 · 고객센터로 넘기는지 스스로 답하는지

### TC-24: 메일 읽음 상태 이상 (장문 상황 서술)
- **질문**: `새로운 메일을 읽지도 않았는데 읽은것으로 표시되며 새로운 메세지가 왔는지 확인을 해보면 이미 누군가 읽은것 처럼 되어있는데 왜 그런가요?`
- **관찰 포인트**: **30문항 중 가장 긴 서술형** — 핵심 증상을 정확히 추출하는지 · 원인 후보 분기(공용 메일함·IMAP 다중 접속·미리보기 설정) · 보안 우려(타인 열람)에 대한 대응 · 답변 길이·구조

### TC-25: 직원 초대 방법
- **질문**: `하이웍스에 직원을 초청하는 방법을 알려줘`
- **관찰 포인트**: 초대/사용자 추가 경로 제시 · 라이선스·요금 영향 언급 여부 · TC-02(조직도 멤버 등록)와 답변이 구별되는지

### TC-26: 출근하기 버튼 미동작
- **질문**: `출근하기가 안눌러져`
- **관찰 포인트**: 근태 기능 장애 원인 분기(IP 제한·근무제 미설정·시간대) · 자가 점검 안내 · 구어체 단문 이해

### TC-27: 전체공유 캘린더 공유대상 추가
- **질문**: `전체공유 캘린더 공유대상 추가하는 방법은?`
- **관찰 포인트**: 캘린더 종류(개인/부서/전체공유) 구분 정확도 · 공유대상 설정 경로 · 권한 조건 언급 · **세부 설정 문항**

### TC-28: 메일함 용량 확인 위치 (구어체 단문)
- **질문**: `메일함 용량확인 어디서해?`
- **관찰 포인트**: 메일 용량 확인 **메뉴 경로**를 정확히 제시하는지 · 개인(내 메일함) / 관리자(오피스 전체 용량) 경로 구분 · 구어체 단문 의도 파악
- **변경 이력**: 2026-09-08 컨플 질문지 v30 반영 — 구 문항 `로그인 2단계 인증 해제방법 알려줘` (회차 1·3 결과는 구 문항 기준)

### TC-29: 조직명 변경 메뉴
- **질문**: `조직 명을 바꾸고 싶은데 어느 메뉴로 가야하지?`
- **관찰 포인트**: 회사명 vs 부서명 vs 도메인 중 무엇으로 해석하는지(**모호성 처리**) · 관리자 경로 제시 · 되물음 여부

### TC-30: 상신한 품의서 수정
- **질문**: `품의서 올린걸 수정하고싶어`
- **관찰 포인트**: 결재 진행 상태별 수정 가능 여부 설명 · 회수 후 재상신 절차 안내 · 전자결재 정책 이해도
