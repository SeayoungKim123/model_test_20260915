# 시나리오: 모델 비교 — B · GPT 5.6 Terra (계정: 일반 사용자2 전용)

## 메타 정보
- **ID**: SCN-02
- **우선순위**: P0
- **목적**: 대표님이 제공한 **동일 프롬프트 세트**를 GPT 5.6 Terra 로 실행해, **답변 내용**과 **응답 속도(체감 대기)** 를 실측·캡처한다. 짝 시나리오 `scenarios/01-모델비교-A-Sonnet5.md` (Claude Sonnet 5) 와 **같은 프롬프트·같은 환경·다른 모델·다른 계정**으로 실행해 모델 간 A/B 비교 원천 데이터를 만든다. 판정보다 **증거 수집**이 목적인 비교 시나리오다.
- **지정 모델**: **GPT 5.6 Terra** — 이 시나리오·이 계정에서 **오직 이 모델만** 사용한다.
- **비교 축**:
  - **A = Claude Sonnet 5** ← `scenarios/01-모델비교-A-Sonnet5.md` (일반 사용자1)
  - **B = GPT 5.6 Terra** ← 이 시나리오 (일반 사용자2)
  - 두 시나리오는 **같은 환경(env)** 에서 실행해야 비교가 성립한다 (dev↔dev, prd↔prd). 매뉴얼 에이전트 O/X 축(dev vs prd)은 이 시나리오의 비교 대상이 아니다.
- **프롬프트 원본**: `scenarios/_prompts/모델비교-프롬프트.md` — **아래 TC 의 질문은 그 파일의 P번호를 원문 그대로 복사한 것**이다 (P01→TC-01 …). 원문을 바꿀 때는 원본 파일을 먼저 고치고 01·02 양쪽을 다시 동기화한다.
- **사전 조건**:
  - **테스트 계정: `environments/{env}.md` 의 "일반 사용자2"** 로 로그인. **이 계정은 GPT 5.6 Terra 전용** — 다른 모델로 전송하지 않는다 (계정별 모델 고정이 비교 설계의 전제).
  - **TC 1건 = 새 대화 1개.** 좌측 **새 대화** 를 눌러 빈 컨텍스트를 만든 뒤 질문을 전송한다. 앞 문항의 대화를 이어서 쓰지 않는다.
  - 새 대화 진입 후 하단 **모델 선택기에서 `GPT 5.6 Terra` 를 지정**하고, 전송 직전에 선택기 표시가 `GPT 5.6 Terra` 인지 **TC 마다 재확인**한다. 다른 모델이 선택돼 있으면 반드시 변경. 목록에 없거나 변경 불가면 그 TC 는 `SKIP` + note 에 "모델 미제공" 기록 — **다른 모델로 대체 전송 절대 금지.**
  - 매뉴얼/에이전트 관련 토글·선택 항목은 **기본 상태 그대로** 두고 note 에 노출된 명칭·상태만 기록한다 (01·02 가 같은 상태여야 함).
  - 코드 인터프리터 등 다른 부가 기능은 **건드리지 않는다**.
- **검증 규칙**:
  - **직접 조작·검색 금지.** 오직 채팅창에 질문만 전송하고 AI 응답을 관찰한다.
  - **판정 기준은 "응답 성립" 여부만** — 답변 품질·정확도는 사람이 비교할 몫이므로 FAIL 사유로 삼지 않는다.
    - `PASS`: 답변이 정상 생성되고 스트리밍이 완료됨
    - `FAIL`: 오류 메시지 · 무응답 · 응답 중단 · TC 타임아웃(180초) 초과 · 답변이 비어 있음
    - `SKIP`: 지정 모델 미제공 등 실행 자체가 불가
  - **각 TC 필수 산출물 3종**:
    1. `wait_ms` — 전송 직전 `t_send` → 응답 완료 `t_done` 실측 (**속도 비교의 원천 데이터. 추정값 금지.**)
    2. **답변 전문 스크린샷** — 1화면을 넘으면 `03b-after`·`03c-after` … 로 **다장 캡처**
    3. `note` — **실제 사용된 모델명(선택기 표시값)** + 답변 요지 2~3문장 + 근거 문서·링크 인용 여부 + 되물음 여부
  - `in_tokens`/`out_tokens` 가 화면에 표시되면 기록, 없으면 `null`.
  - **멀티턴 금지** — 1문항 = 1턴. AI 가 되물어도 후속 답변 없이 "되물음으로 종료" 를 note 에 기록하고 다음 TC 로.
  - **시각화 산출물 기록 (전 문항 공통 — 모든 프롬프트가 "시각화해줘" 로 끝남)**: note 에 시각화 **형태**를 반드시 적는다 — `다이어그램(mermaid/렌더)` / `표` / `ASCII 아트` / `이미지 생성` / `코드블록만(렌더 안 됨)` / `미제공(텍스트만)`. 시각화가 없어도 응답이 성립했으면 **PASS** (형태 차이는 사람이 비교). 이미지·다이어그램이 **렌더링되는 경우 렌더 완료 시점**이 `t_done` 이며, 캡처에 렌더 결과가 반드시 포함되어야 한다.
  - **글자 깨짐 확인 (전 문항 공통 — 대표님 지시)**: 응답 완료 후 답변 전문을 **스크린샷 육안 + `browser_snapshot` 텍스트** 양쪽으로 훑어 깨진 글자가 있는지 확인한다. 대상: 한글 깨짐(`ë°`·`?` 등 모지바케) · 대체 문자 `�`(U+FFFD) · 이모지/특수기호가 `□` 로 표시 · 다이어그램·표 안의 한글이 잘리거나 겹침 · 마크다운 기호(`**`, `|`, `###`, mermaid 코드)가 렌더되지 않고 날것으로 노출. note 에 **`글자깨짐: 없음`** 또는 **`글자깨짐: 있음 — {위치}·{형태}`** 를 **반드시** 적는다. 있으면 그 부분을 크롭 캡처 `04-glitch`(여러 곳이면 `04b`·`04c`…)로 남긴다. 일부 깨짐은 `PASS` 유지 + 기록, 본문 대부분이 읽을 수 없으면 `FAIL` + note `"글자깨짐-판독불가"`.
  - 스크린샷 슬러그는 **`model-cmp-terra-{env}`** (예: `model-cmp-terra-dev-tc01-03-after.png`). 나머지 파일명 규칙은 `/qa-run` SKILL.md 단일 출처.
  - 한 TC 가 실패해도 **끝까지 진행**. TC 간 의존 없음 → `BLOCKED` 는 발생하지 않는다.
- **타임아웃 (이 시나리오 한정 상향)**: TC 1건 **180초**, 시나리오 전체 **25분**. 장문 개념 설명 + 시각화 생성이라 매뉴얼 문항(90초)보다 길게 잡는다. 초과 시 `FAIL` + note `"timeout"`.

## 사용자 흐름

실사용자가 AI채팅에 같은 요청을 던졌을 때 모델에 따라 답변·속도가 어떻게 다른지 재현한다. 문항마다 맥락 없이 처음부터 묻는 것이 핵심이라 **매 문항 새 대화**로 시작한다.

1. **새 대화 진입** — 빈 컨텍스트 확인
2. **모델 지정·재확인** — `GPT 5.6 Terra`
3. **질문 전송** — `t_send` 기록 직후 전송
4. **응답 완료 대기** — 스트리밍 종료 시점에 `t_done` 기록
5. **답변 전문 캡처** — 길면 다장, 토큰 표시 있으면 함께 기록
6. `progress.jsonl` 즉시 append → 다음 문항은 **다시 새 대화**

## 공통 조작 순서 (전 TC 동일)

1. 좌측 **새 대화** 클릭 → 빈 컨텍스트 확인
2. 하단 모델 선택기에서 **GPT 5.6 Terra** 선택 → 표시값 재확인
3. 채팅창에 **질문 원문 그대로** 입력 → `02-prompt` 캡처
4. `t_send = browser_evaluate(() => Date.now())` → **곧바로** 전송
5. 응답 스트리밍 종료 확인 → 즉시 `t_done` 기록
6. 답변 전문 캡처 (`03-after`, 넘치면 `03b`·`03c` …)
7. `progress.jsonl` 1줄 append

> 아래 각 TC 는 **질문 원문**과 **관찰 포인트**만 다르다. 조작 순서는 위와 동일.

## 테스트 케이스

> 5문항 모두 **"시각화해줘"** 로 끝나는 장문 개념형 질의다. 답변이 길고 다이어그램·표가 섞이므로 **다장 캡처**와 **시각화 형태 기록**이 핵심 산출물이다. 질문은 `_prompts/모델비교-프롬프트.md` P01~P05 원문 그대로(특수 따옴표 포함).

### TC-01: 업무형 AI 에이전트 워크플로우 설계 (Salesforce Agentforce 사례)
- **질문**: `Salesforce Agentforce 사례처럼 업무형 AI 에이전트를 워크플로우 단위로 설계하는 방법을 알려줘. 챗봇 기능 기획과의 차이, 그리고 B2B 서비스에서 먼저 검증할 지점을 간단히 정리해줘. 시각화해줘.`
- **관찰 포인트**: Agentforce 를 실제 사실에 근거해 설명하는지(환각 여부) · 챗봇 기획 vs 에이전트 설계 차이를 축(트리거·목표·도구·권한·종료 조건 등)으로 구분하는지 · B2B 선검증 지점을 구체적으로 제시하는지 · **시각화 형태**(다이어그램/표/ASCII/이미지/미제공)

### TC-02: AI 에이전트 워크 그래프 개념과 구조화 방법
- **질문**: `AI 에이전트의 워크 그래프가 무엇인지 알려줘. 기획자가 사람·업무·권한·의존성을 어떤 방식으로 구조화하면 자동화 품질을 높일 수 있는지 설명해줘. 시각화해줘.`
- **관찰 포인트**: "워크 그래프" 정의를 단정적으로 지어내지 않고 용어 출처·맥락을 밝히는지 · 사람·업무·권한·의존성 4요소를 노드/엣지로 구조화해 보여주는지 · 자동화 품질과의 연결 논리 · **시각화 형태**(그래프 다이어그램 여부)

### TC-03: AI 시대 PM 의 ‘판단 병목’ 개념과 적용
- **질문**: `AI가 PM 실행을 빠르게 하면서 말하는 ‘판단 병목’이 뭔지 알려줘. 플래너가 기능 우선순위와 AI 결과 검증에 적용할 방법도 간단히 정리해줘. 시각화해줘.`
- **관찰 포인트**: ‘판단 병목’ 을 명확히 정의하는지 · 기능 우선순위·AI 결과 검증 두 적용처에 각각 실행 가능한 방법을 주는지 · **원문의 특수 따옴표(‘ ’)가 입력창에 그대로 들어갔는지 `02-prompt` 에서 확인** · **시각화 형태**

### TC-04: Atlassian 상시 에이전트형 개발 기능과 기획 설계
- **질문**: `Atlassian의 항상 켜진 에이전트형 개발 기능이 무엇인지 알려줘. 기획자가 백로그·승인 지점·품질 기준을 어떻게 설계해야 하는지도 간략히 정리해줘. 시각화해줘.`
- **관찰 포인트**: Atlassian 의 실제 기능·제품명을 정확히 특정하는지, 불확실하면 정직하게 밝히는지(환각 여부) · 백로그·승인 지점·품질 기준 3요소를 모두 다루는지 · **시각화 형태**

### TC-05: Mind the Product 의 환경적 제품 의사결정과 평가 기준
- **질문**: `Mind the Product가 말한 환경적 제품 의사결정이 무엇인지 알려줘. 대규모 AI 기능의 우선순위를 정할 때 비용·성능·에너지 사용을 함께 평가하는 간단한 기준도 만들어줘. 시각화해줘.`
- **관찰 포인트**: Mind the Product 출처 언급의 정확성(실제 글·개념 인용인지, 지어낸 것인지) · 비용·성능·에너지 3축 평가 기준을 표·스코어카드 등 바로 쓸 수 있는 형태로 만드는지 · **시각화 형태**
